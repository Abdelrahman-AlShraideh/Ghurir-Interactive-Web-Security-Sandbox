SECURITY LAB 03

File Upload Vulnerabilities

Learn how insecure file upload validation can allow dangerous files to enter an application.

OWASP: A04:2021 - Insecure Design CWE-434

01. Understanding the Vulnerability

Unrestricted File Upload occurs when an application accepts files without properly validating their type, content, or permitted extensions. An attacker may upload a dangerous file that can affect the application or its users.

Why Is File Validation Important?

Checking only a filename extension is not sufficient. Applications should validate allowed file types, inspect file content, generate safe server-side names, and store uploads in a non-executable location.

upload-fixed.js JavaScript 
function uploadFile(file) {
    const parts = file.name.toLowerCase().split(".");
    const extension = parts.pop();
    const allowed = ["jpg", "jpeg", "png"];
    if (!allowed.includes(extension)) return "Rejected";
    if (!["image/jpeg", "image/png"].includes(file.type)) return "Rejected";
    if (!matchesFileSignature(file)) return "Rejected";
    if (hasDangerousInnerExtension(parts)) return "Rejected";
    const safeName = generateRandomName(extension);
    storeOutsideWebRoot(safeName, file);
    disableServerExecution(safeName);
    return "Upload accepted safely";
}

04. Impact

Dangerous file uploads may expose users to malicious content, enable unauthorized file storage, or lead to server compromise when uploaded files are executed by the hosting environment. The actual impact depends on how the application stores and serves files.

05. Security Recommendations

  • Allow only explicitly permitted file types.
  • Validate file content and signatures, not only extensions.
  • Generate random server-side filenames.
  • Set strict file size limits.
  • Store uploaded files outside the web root when possible.
  • Prevent uploaded files from being executed by the server.
