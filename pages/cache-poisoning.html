SECURITY LAB 01

Web Cache Poisoning

Learn how an improperly configured cache can store an attacker-influenced response and serve it to other users.

OWASP: A05:2021 - Security Misconfiguration CWE-444

01. Understanding the Vulnerability

Web Cache Poisoning occurs when a cache stores a response that was influenced by an input not included in its cache key. Other users may then receive the poisoned response.

function getCacheKey(request) {
    return request.url;
}

function buildResponse(request) {
    const host = request.headers["X-Forwarded-Host"];
    return { assetHost: host || "trusted.example" };
}

function handleRequest(request) {
    const key = getCacheKey(request);
    if (cache.has(key)) return cache.get(key);
    const response = buildResponse(request);
    cache.set(key, response);
    return response;

Cache Key

The value used by a cache to identify and retrieve a stored response.

Unkeyed Input

An input that influences the response but is not represented in the cache key.

04. Impact

A poisoned cache may distribute attacker-controlled content to multiple visitors. Depending on the application, this can lead to phishing, content manipulation, or other attacks.

05. Security Recommendations

  • Include every response-affecting input in the cache key.
  • Validate and normalize untrusted headers before using them.
  • Disable shared caching for sensitive or user-specific responses.
  • Test cache behavior with different headers and request variations.
