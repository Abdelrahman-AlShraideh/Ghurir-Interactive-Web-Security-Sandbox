SECURITY LAB 02

OAuth Account Linking Flaw

Learn how insecure account linking can allow an attacker to associate an external identity with another user's account.

OWASP: A07:2021 - Identification and Authentication Failures CWE-287

01. Understanding the Vulnerability

What is Account Linking?

Account linking allows users to connect an external identity, such as Google, to an existing account. A vulnerability occurs when the application links that identity without properly verifying ownership and authorization.

THE VULNERABILITY SCENARIO

How Does the Attack Happen?

Consider an application that automatically links external identities based only on matching email addresses.

01

Existing Victim Account

The victim already has an account in the application.

victim@example.com
02

Attacker's Identity

The attacker presents an external identity containing the victim's email address.

email_verified: false
03

Unsafe Account Lookup

The application searches for an account using the email address alone.

findUserByEmail(email)
04

Unauthorized Linking

The application links the attacker's external identity to the victim's account without the victim's approval.

Account linked incorrectly
ROOT CAUSE

Why Does This Happen?

The application treats a matching email address as proof of ownership. However, the identity token can have a valid signature while the email remains unverified. The application must also require authentication to the existing account and explicit approval from its owner.

03. Vulnerable vs Fixed Implementation

Compare an unsafe account-linking implementation with a safer approach that verifies identity and requires authorization from the existing account owner.

function linkAccount(user, identity) {
    const email = identity.email;

    const existingUser = findUserByEmail(email);

    if (existingUser) {
        existingUser.providerId = identity.subject;

        return "Account linked";
    }

    return "User not found";
}

AFTER FIX

Fixed Implementation

PROTECTED
account-linking-fixed.js JavaScript 
function linkAccount(user, identity) {
    if (!user.isAuthenticated) throw new Error("Login required");

    if (!identity.signatureValid ||
        !identity.issuerTrusted ||
        !identity.subject) {
        throw new Error("Invalid identity");
    }

    if (!identity.emailVerified) {
        throw new Error("Email not verified");
    }

    if (!user.confirmedLinking) {
        throw new Error("Approval required");
    }

    saveIdentity(user.id, {
        issuer: identity.issuer,
        subject: identity.subject
    });

    return "Account linked safely";
}

04. Impact

Improper account linking may allow an attacker to associate an external identity with another user's account. Depending on the application's authentication design, this can lead to unauthorized account access, account takeover, and exposure of private information.

05. Security Recommendations

  • Require the user to authenticate to the existing account before linking another identity.
  • Require explicit user confirmation before completing the linking operation.
  • Validate the identity token, including its signature, issuer, audience, and expiration.
  • Use the trusted combination of issuer and subject as the external identity identifier.
  • Do not rely on an email address alone to identify or link an account.
  • When email is used, verify that the identity provider confirms email ownership.
